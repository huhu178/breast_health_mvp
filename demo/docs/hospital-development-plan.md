# 医院场景多结节健康管理系统开发计划 V1.0

## 1. 文档目的

本文件用于把《医院场景多结节健康管理系统项目开发需求书 V1.0》拆分为可执行开发任务，明确开发顺序、阶段目标、交付内容和验收重点。

关联文档：

- `docs/hospital-project-requirements.md`
- `docs/hospital-data-model.md`
- `docs/hospital-api-spec.md`
- `docs/hospital-ui-pages.md`

## 2. 开发原则

1. 先跑通医院场景核心闭环，再补管理看板和规则增强。
2. 先做数据关系和权限基础，再做页面。
3. 医生端保持轻量，只查看患者并填写报告随访建议。
4. 科室主任只查看本科室数据，不参与业务操作。
5. 患者端以小程序为主，公开打卡链接作为补充。
6. 一期独立运行，不把 HIS/EMR/PACS 对接作为验收条件。

## 3. 阶段拆分

### 3.1 V1.0 核心闭环

目标：完成患者从建档到报告、医生建议、随访任务、患者反馈的基础闭环。

后端任务：

- 扩展用户角色：健康管理师、医生助手、医生、科室主任、系统管理员。
- 增加科室字段和医生归属科室字段。
- 患者增加所属科室、主要负责医生、负责管理人员字段。
- 完善多结节数据结构。
- 增加报告随访建议数据结构。
- 完善患者详情聚合接口。
- 增加医生患者列表和报告随访建议接口。
- 增加基础数据权限过滤。

前端任务：

- 登录后识别角色。
- 调整医院场景导航。
- 患者详情页补齐完整链条。
- 患者建档表单增加所属科室、主要负责医生。
- 多结节区域支持查看和编辑。
- 报告详情增加报告随访建议区域。
- 医生工作台增加“我的患者”和“待填写建议”。

患者端任务：

- 小程序随访任务详情。
- 小程序随访问卷提交。
- 小程序上传复查资料。
- 公开打卡链接作为补充入口。

验收重点：

- 健康管理师/医生助手能完成患者建档、报告处理、随访任务。
- 医生能看到本人患者并填写报告随访建议。
- 患者能通过小程序或公开链接提交随访反馈。
- 患者详情页能展示完整管理链条。

### 3.2 V1.1 科室管理增强

目标：完善科室主任看板和管理统计。

后端任务：

- 增加科室主任数据范围过滤。
- 增加科室统计接口。
- 增加医生维度统计接口。
- 增加异常患者和超期随访统计接口。
- 增加操作日志记录。

前端任务：

- 科室主任看板。
- 科室患者列表。
- 医生维度统计。
- 风险分布和随访完成率图表。
- 异常患者列表。

验收重点：

- 科室主任只能查看本科室数据。
- 看板统计和患者列表数据一致。
- 可以从看板进入患者详情查看。

### 3.3 V1.2 知识库和规则增强

目标：增强随访计划推荐的可解释性和可维护性。

后端任务：

- 随访知识库规则增加版本、来源、确认人、启停状态。
- 随访计划记录推荐依据。
- 随访计划记录人工调整原因。
- 增加规则列表、启停、编辑接口。

前端任务：

- 随访知识库规则管理页面。
- 随访计划推荐依据展示。
- 随访计划调整原因填写。
- 规则版本和确认人展示。

验收重点：

- 系统能展示随访计划为什么被推荐。
- 人工调整计划有记录可追溯。
- 规则可启用、停用和维护。

## 4. 推荐开发顺序

1. 数据模型和迁移。
2. 角色权限和数据范围。
3. 患者详情聚合接口。
4. 患者建档和多结节维护。
5. 报告随访建议。
6. 随访任务和患者端反馈。
7. 医生工作台。
8. 科室主任看板。
9. 知识库规则增强。

## 5. 风险点

- 现有系统已有多场景入口，需要收敛医院场景，避免页面混乱。
- 现有患者和结节字段可能是混合字段，后续要逐步拆清患者层和结节层。
- 权限过滤必须从接口层实现，不能只靠前端隐藏。
- 小程序和公开链接都能提交随访反馈，需要统一落到同一套随访记录。
- 报告随访建议不要扩展成复杂医生工作流，否则会偏离一期目标。

## 6. 验收清单

- 健康管理师可新增患者并维护多结节。
- 医生助手权限与健康管理师一致。
- 医生只能查看本人相关患者。
- 医生可填写报告随访建议。
- 科室主任只能查看本科室患者和统计。
- 患者详情展示基础信息、结节、报告、风险、报告随访建议、随访计划、随访任务。
- 小程序可提交随访反馈。
- 公开链接可作为补充提交随访反馈。
- 随访异常可进入健康管理师/医生助手处理队列。
- 报告归档后不可直接覆盖编辑。
