# 医院场景多结节健康管理系统项目开发需求书 V1.0

## 1. 项目背景

本项目面向医院乳腺健康管理及多结节患者随访场景，服务对象包括健康管理师、医生助手、医生、科室主任等院内人员。系统用于将患者建档、结节资料管理、影像报告上传、风险评估、医生复核、随访计划生成、随访执行跟踪、科室数据看板等流程集中到一个平台中。

当前项目已有患者管理、报告审核、风险评估、随访知识库、随访任务下发、患者打卡、执行跟踪等功能雏形。医院场景版本需要在现有能力基础上，进一步明确院内角色权限、科室与医生数据范围、多结节管理模型，以及医生和科室主任的查看与复核工作台。

一期系统按独立系统建设，不直接对接 HIS、EMR、PACS 等医院信息系统。系统支持人工录入、文件上传、规则推荐和人工审核，后续预留医院系统接口扩展能力。

## 2. 项目目标

1. 建立院内统一的多结节患者健康管理档案。
2. 支持健康管理师和医生助手完成患者建档、资料维护、报告处理、随访计划创建和随访执行。
3. 支持医生查看自己相关患者，填写报告随访建议。
4. 支持科室主任查看本科室患者、医生、风险分层、随访完成情况等管理数据。
5. 支持基于知识库规则自动推荐随访计划，同时允许人工调整。
6. 实现患者从建档、报告、风险评估、报告随访建议、随访任务、执行跟踪到复查回收的闭环管理。
7. 以小程序作为患者端主要入口，公开打卡链接作为补充方式，并为后续对接 HIS、EMR、PACS、检查报告系统留出扩展空间。

- 健康报告生成与审核
- 报告随访建议填写
- 随访知识库与模板管理

- 随访任务下发与执行跟踪
- 医生工作台
- 科室主任看板
- 健康管理师/医生助手操作工作台
- 操作日志和基础数据安全控制

### 3.2 一期暂不建设范围

- 与医院 HIS、EMR、PACS 的正式接口对接

### 3.3 后续扩展范围

- HIS/EMR/PACS 对接

## 4. 用户角色与权限

### 4.1 健康管理师

健康管理师是核心业务操作人员，负责患者健康管理流程推进。

主要权限：

- 新增、编辑患者基础信息
- 维护患者多结节信息
- 上传影像报告、检查资料和健康档案
- 发起报告生成和报告审核流程
- 查看风险评估结果
- 创建、确认、调整随访计划
- 执行随访任务并记录随访结果
- 处理异常随访反馈
- 分配或关联负责医生
- 查看自己负责患者和任务统计

### 4.2 医生助手

医生助手与健康管理师权限一致，作为院内业务协助人员参与患者管理和随访执行。

主要权限：

- 与健康管理师相同的患者建档、资料维护、随访任务、报告处理权限
- 可协助医生整理患者资料和复核前信息
- 可根据医生要求补充随访计划和任务记录

### 4.3 医生

医生以查看和报告随访建议填写为主，不承担日常运营维护。

主要权限：

- 查看与本人相关的患者
- 查看患者基础信息、结节信息、影像报告、健康报告、随访记录
- 查看系统风险分层和随访计划
- 填写报告随访建议
- 对待复核报告或异常随访进行确认
- 查看我的患者、待复核、异常提醒等个人工作台

医生原则上不编辑患者基础档案，不删除资料，不批量调整随访规则。

### 4.4 科室主任

科室主任以管理看板和监督查看为主。

主要权限：

- 查看本科室患者总览
- 查看本科室医生相关患者和任务情况
- 查看风险患者分布
- 查看随访完成率、超期任务、异常患者列表
- 查看报告审核和医生复核统计
- 查看单个患者详情和报告随访建议

科室主任不参与日常建档、随访执行和意见填写，仅查看本科室相关数据。

### 4.5 系统管理员

系统管理员负责基础配置和账号管理。

主要权限：

- 用户账号管理
- 角色权限配置
- 科室、医生、健康管理师配置
- 字典项配置
- 知识库和模板配置权限管理
- 系统日志查看

## 5. 数据权限原则

系统采用“角色权限 + 数据范围”的方式进行控制。

- 健康管理师/医生助手：可操作自己负责、被分配或被授权的患者。
- 医生：可查看本人关联患者，可填写报告随访建议。
- 科室主任：可查看本科室范围内患者、医生和统计数据。
- 系统管理员：管理账号和配置，不默认参与患者医疗内容处理。

患者与医生、科室的关系需要保持清晰。一期采用一个患者归属一个科室、一个患者有一个主要负责医生的方式；系统支持一个患者下存在多个结节。

## 6. 核心业务对象

### 6.1 患者

患者是系统管理的基础对象。

基础字段包括：

- 患者姓名
- 性别
- 年龄
- 手机号
- 就诊号/门诊号/住院号，可选
- 所属科室
- 来源渠道
- 负责健康管理师/医生助手
- 主要负责医生
- 当前状态
- 风险等级
- 建档时间
- 最近随访时间
- 下次随访时间

### 6.2 结节/病灶

结节/病灶是医院场景的核心管理对象。系统应支持一个患者下存在多个结节或多个结节类型。

结节字段包括：

- 结节类型：乳腺、肺部、甲状腺等
- 结节编号
- 所属部位
- 左右侧/象限/叶段等定位信息
- 大小
- 数量
- 影像特征
- BI-RADS/Lung-RADS/TI-RADS 等分级
- 风险等级
- 关联影像报告
- 关联医生，可选
- 当前随访计划
- 复查变化情况

### 6.3 健康档案

健康档案记录患者的病史、家族史、症状、生活方式、检查资料等。

主要内容包括：

- 基础健康信息
- 既往史
- 家族史
- 症状信息
- 影像检查信息
- 中医/舌诊/手诊等健康评估信息，可选
- 生活方式信息
- 心理、饮食、运动相关信息

### 6.4 影像报告与检查资料

系统支持人工上传报告文件和结构化录入关键字段。

资料类型包括：

- 超声报告
- CT 报告
- 钼靶报告
- MRI 报告
- 其他检查资料
- 图片、PDF、结构化文本

### 6.5 健康报告

健康报告用于对患者当前情况进行健康管理解释和随访建议输出。报告内容需要经过审核后形成最终版本。

报告状态包括：

- 未生成
- 草稿
- 待审核
- 已审核
- 已归档

医生或授权人员可填写审核意见。最终报告归档后原则上不可再次编辑，只能新增版本或补充记录。

### 6.6 随访计划

随访计划用于定义患者或结节后续管理周期。

计划字段包括：

- 计划名称
- 关联患者
- 关联结节
- 关联知识库规则
- 风险等级
- 随访周期
- 随访方式
- 计划节点
- 负责人员
- 当前状态
- 调整记录

### 6.7 随访任务

随访任务是计划落地执行的具体事项。

任务字段包括：

- 任务标题
- 关联患者
- 关联计划
- 任务类型
- 计划执行时间
- 实际执行时间
- 执行人员
- 触达方式
- 患者反馈
- 是否异常
- 处理状态
- 医生是否需查看

## 7. 核心业务流程

### 7.1 患者建档流程

1. 健康管理师或医生助手新增患者。
2. 录入基础信息、来源科室、联系方式。
3. 添加一个或多个结节/病灶信息。
4. 上传检查报告或录入影像关键字段。
5. 系统生成初始风险分层。
6. 关联负责医生和管理人员。
7. 患者进入管理队列。

### 7.2 报告处理流程

1. 操作人员选择患者并发起报告生成。
2. 系统根据档案、检查资料、风险规则和知识库生成报告草稿。
3. 健康管理师/医生助手检查资料完整性。
4. 医生查看报告草稿并填写报告随访建议。
5. 报告审核通过后写入最终报告。
6. 最终报告锁定，不允许直接覆盖修改。

### 7.3 报告随访建议流程

1. 医生进入个人工作台。
2. 查看我的患者、待复核报告、异常随访提醒。
3. 打开患者详情。
4. 查看患者档案、结节信息、报告、随访记录。
5. 填写报告随访建议。
6. 系统记录建议内容、医生、时间和关联报告/患者。

### 7.4 随访计划生成流程

系统支持“规则自动推荐 + 人工确认调整”。

1. 系统根据结节类型、分级、风险等级、年龄、症状、报告结论等匹配知识库规则。
2. 自动推荐随访计划和随访节点。
3. 健康管理师或医生助手确认计划。
4. 操作人员可修改周期、方式、节点和负责人。
5. 医生可根据医学判断补充报告随访建议。
6. 系统记录自动生成依据和人工调整原因。

### 7.5 随访执行流程

1. 系统按计划生成随访任务。
2. 健康管理师或医生助手通过小程序、电话、企微、短信、公开链接等方式执行随访。
3. 患者提交反馈或工作人员记录随访结果。
4. 系统识别异常反馈。
5. 异常任务进入人工处理队列。
6. 需要医生判断时推送至医生工作台。
7. 随访完成后生成下一次任务或更新计划状态。

### 7.6 科室主任查看流程

1. 科室主任进入科室看板。
2. 查看本科室患者总数、风险分布、随访完成率、报告审核情况。
3. 按医生、风险等级、结节类型、随访状态筛选。
4. 查看异常患者和超期任务。
5. 进入患者详情查看完整记录。

## 8. 功能模块需求

### 8.1 登录与权限模块

- 支持账号密码登录
- 支持角色识别
- 支持不同角色进入不同默认工作台
- 支持菜单权限控制
- 支持按钮级操作权限
- 支持数据范围控制

### 8.2 患者管理模块

- 患者新增、编辑、查看
- 患者列表筛选
- 按姓名、手机号、风险等级、结节类型、科室、医生筛选
- 患者状态管理
- 患者详情页
- 患者完整管理链条展示

### 8.3 多结节管理模块

- 一个患者支持多个结节记录
- 支持乳腺、肺部、甲状腺等结节类型
- 支持多结节组合场景
- 支持每个结节独立记录分级、部位、大小、影像特征
- 支持按结节维度生成风险和随访计划
- 支持复查前后变化记录

### 8.4 影像报告模块

- 上传报告文件
- 删除或作废错误文件
- 录入报告关键字段
- 关联患者和结节
- 展示历史报告
- 支持报告结构化字段供风险评估和报告生成使用

### 8.5 风险评估模块

- 根据知识库规则和影像分级生成风险分层
- 支持低风险、中风险、高风险三档
- 支持显示风险来源和依据
- 支持高风险患者优先展示
- 风险结果用于队列排序、报告审核、随访计划和异常提醒

风险分层仅作为健康管理工作流分层，不作为诊断结论或治疗决策。

### 8.6 报告审核模块

- 生成报告草稿
- 查看报告内容
- 填写审核意见
- 审核通过后归档
- 归档后锁定
- 支持从报告审核后创建首次随访任务

### 8.7 随访知识库与模板模块

- 管理不同结节类型的随访知识
- 管理不同风险等级的随访模板
- 支持节点配置
- 支持随访话术配置
- 支持规则启停
- 支持规则版本管理，后续可扩展

### 8.8 随访计划与任务模块

- 自动推荐随访计划
- 人工创建随访计划
- 人工调整随访计划
- 生成随访任务
- 下发随访任务
- 查看随访任务状态
- 记录随访执行结果
- 异常反馈标记
- 执行跟踪回看

### 8.9 医生工作台

医生工作台面向医生本人，重点是查看和复核。

页面内容包括：

- 我的患者
- 待复核报告
- 异常随访提醒
- 高风险患者
- 近期复查患者
- 报告随访建议填写入口

### 8.10 科室主任看板

科室主任看板面向科室管理。

页面内容包括：

- 科室患者总数
- 本月新增患者
- 风险分布
- 结节类型分布
- 医生患者数量
- 医生待复核数量
- 随访完成率
- 超期随访任务
- 异常患者列表

### 8.11 健康管理师/医生助手工作台

操作人员工作台面向日常工作推进。

页面内容包括：

- 今日待随访

- 待上传报告
- 待报告审核
- 待医生复核
- 异常患者
- 超期任务
- 快捷新增患者

## 10. 知识库与随访规则说明

系统需要同时支持人工创建和规则自动生成随访计划。

人工创建适用于特殊患者、医生临时要求、规则尚未覆盖的情况。优点是灵活，缺点是依赖人工经验，容易遗漏。

规则自动生成适用于标准化随访管理。系统根据知识库规则、结节类型、影像分级、风险等级和患者情况自动推荐随访计划。优点是标准化、可追溯、不容易遗漏，缺点是前期需要整理规则，并允许医生和操作人员调整。

一期建议采用：

> 知识库规则自动推荐，人工确认后生效，允许医生或授权操作人员调整。

系统需记录：

- 推荐规则
- 推荐原因
- 原始计划
- 调整后计划
- 调整人员
- 调整时间
- 调整理由

## 11. 医院系统对接策略

一期系统独立运行，暂不强制对接医院系统。

独立系统一期能力：

- 人工录入患者信息
- 人工上传检查报告
- 人工维护医生和科室
- 人工创建和调整随访计划
- 系统内部完成风险评估和任务流转

后续对接可能涉及：

- HIS：患者基本信息、挂号、就诊记录
- EMR：病历、诊断、医生记录
- PACS：影像文件和影像报告
- LIS：检验结果
- 院内消息或企业微信：消息通知和任务提醒

对接复杂点包括：

- 医院信息科协调
- 接口标准差异
- 患者身份匹配
- 数据权限和审计
- 网络和部署环境限制
- 各医院系统厂商差异

因此需求书中应明确：一期预留接口能力，但不把正式对接作为一期验收条件。

## 12. 患者端小程序需求

一期患者端以小程序为主，公开打卡链接作为补充入口。

### 12.1 小程序主要能力

- 手机号验证码登录或绑定
- 查看本次随访任务
- 填写随访问卷
- 上传复查报告图片或 PDF
- 查看简化版随访提醒
- 查看简化版健康建议
- 提交异常反馈
- 查看下次随访时间

### 12.2 公开打卡链接能力

公开打卡链接用于补充场景，例如患者未安装小程序、临时随访、短信触达或企微触达。

公开链接页面原则：

- 只展示本次随访所需字段
- 不展示完整患者档案
- 不展示完整影像报告
- 不展示完整健康报告
- 链接应有有效期
- 提交后记录来源为公开链接

### 12.3 患者端可见范围

一期患者端不作为完整患者门户，只承担随访反馈和简化提醒。

患者端可见：

- 本次随访问题
- 下次随访时间
- 简化健康建议
- 上传资料入口

患者端默认不可见：

- 完整院内档案
- 医生工作台内容
- 科室管理数据
- 完整报告，除非医院确认开放

## 13. 非功能需求

### 13.1 数据安全

- 患者隐私信息必须受权限控制
- 不同角色只能访问授权范围内数据
- 关键操作需记录日志
- 文件上传需限制类型和大小
- 后续部署需支持 HTTPS

### 13.2 可追溯性

以下内容需要保留历史记录：

- 患者资料修改
- 影像报告上传和删除
- 风险评估结果
- 报告随访建议
- 报告审核
- 随访计划调整
- 随访任务执行
- 异常处理

### 13.3 易用性

- 健康管理师高频操作步骤要少
- 患者详情页要能看到完整链条
- 医生工作台突出待复核和异常患者
- 科室主任看板突出统计和异常情况
- 列表筛选要支持多条件组合

### 13.4 可扩展性

- 支持新增结节类型
- 支持新增知识库规则
- 支持新增随访模板
- 支持后续对接医院系统
- 支持多医生、多管理人员协作

## 14. 一期验收标准

1. 健康管理师/医生助手可以完成患者建档和多结节信息维护。
2. 系统可以上传并管理患者影像报告。
3. 系统可以根据规则生成风险分层。
4. 系统可以生成健康报告草稿并进入审核流程。
5. 医生可以查看患者并填写报告随访建议。
6. 系统可以基于知识库推荐随访计划。
7. 操作人员可以确认、调整、创建随访任务。
8. 系统可以记录随访执行结果和异常反馈。
9. 医生可以查看异常随访和待复核事项。
10. 科室主任可以查看本科室患者、医生、风险和随访统计。
11. 权限控制可以区分操作角色、医生角色、科室主任角色。
12. 最终报告归档后不可直接覆盖编辑。

## 16. 已确认方案

### 16.1 报告随访建议

医生端只保留“报告随访建议”，不拆分报告审核意见、复查建议、转诊建议、异常处理意见等多种类型。

一期字段采用：

- 报告随访建议内容
- 建议下次随访时间，可选

### 16.2 科室归属

一期不设计协作科室。患者只归属一个科室。

科室主任可查看以下患者：

- 所属科室为本科室的患者

科室主任仅查看数据和患者详情，不填写督办意见，不参与随访执行。

### 16.3 患者和结节负责医生

一期采用“患者主要负责医生”为主的方式。

- 患者层面必须有主要负责医生。
- 结节层面不强制单独指定医生。
- 多结节统一归属到患者主要负责医生名下查看。

### 16.4 健康管理师和医生助手

健康管理师和医生助手在系统中保留为两个角色，但一期权限一致。

界面上可统一展示为“管理人员”或“运营人员”，账号和日志中保留实际角色，方便后续细分权限。

### 16.5 患者端入口

一期患者端以小程序为主，公开打卡链接作为补充入口。

建议登录方式：

- 小程序使用手机号验证码登录或绑定。
- 健康管理师可通过系统生成随访入口，患者点击后进入小程序或公开打卡页面。
- 公开打卡链接页面只展示本次随访所需内容，不展示完整患者隐私信息。

### 16.6 最终报告患者可见范围

一期建议院内人员查看完整报告，患者小程序只展示简化版随访提醒和健康建议。

完整报告是否对患者开放，由医院或科室确认后再配置开放。系统预留患者端查看报告摘要或完整报告的扩展能力。

### 16.7 知识库规则确认

一期知识库规则由项目方整理初版，医生或科室负责人确认后启用。

一期不建设复杂审批流，先支持：

- 规则启用/停用
- 规则版本备注
- 规则来源说明
- 最近更新时间
- 确认人记录

## 18. 报告随访建议结构

医生端建议收敛为“报告随访建议”，不再拆成多类建议，降低医生使用负担。

字段建议：

- 关联患者
- 关联报告
- 关联结节，可选
- 报告随访建议内容
- 建议下次随访时间，可选
- 填写医生
- 填写时间
- 状态：草稿、已提交

报告随访建议进入系统后，应在患者详情页、医生工作台和报告详情中展示。健康管理师或医生助手可根据该建议调整随访计划。

## 19. 患者多结节数据关系

医院场景建议采用以下数据关系：

```text
患者 Patient
  ├─ 健康档案 HealthRecord
  ├─ 结节/病灶 Nodule 1
  │   ├─ 影像报告 ImagingReport
  │   ├─ 风险评估 RiskAssessment
  │   ├─ 医生 Doctor
  │   └─ 随访计划 FollowupPlan
  ├─ 结节/病灶 Nodule 2
  │   ├─ 影像报告 ImagingReport
  │   ├─ 风险评估 RiskAssessment
  │   ├─ 医生 Doctor
  │   └─ 随访计划 FollowupPlan
  ├─ 健康报告 HealthReport
  ├─ 报告随访建议 ReportFollowupAdvice
  └─ 随访任务 FollowupTask
```

设计原则：

- 患者是总入口。
- 结节/病灶是风险和随访的重要依据。
- 一个患者可以有多个结节。
- 一个患者归属一个科室。
- 一个患者有一个主要负责医生，多结节默认归属该医生查看。
- 风险评估可以在患者层展示总风险，也可以在结节层展示单个结节风险。

## 20. 状态流转

## 23. 典型验收用例

### 23.1 健康管理师建档并创建随访

前置条件：健康管理师账号已登录。

步骤：

1. 新增患者。
2. 填写患者基础信息。
3. 添加两个乳腺结节记录。
4. 上传乳腺超声报告。
5. 系统生成风险分层。
6. 生成健康报告草稿。
7. 提交医生复核。
8. 医生填写报告随访建议。
9. 健康管理师确认随访计划。
10. 系统生成随访任务。

预期结果：

- 患者进入随访中状态。
- 患者详情页能看到结节、报告、风险、报告随访建议、随访计划和任务。

### 23.2 医生查看本人患者并填写报告随访建议

前置条件：患者已关联医生。

步骤：

1. 医生登录。
2. 进入医生工作台。
3. 查看待复核患者。
4. 打开患者详情。
5. 查看报告和随访记录。
6. 填写报告随访建议。
7. 提交建议。

预期结果：

- 报告随访建议保存成功。
- 患者详情页和报告详情展示该建议。
- 健康管理师/医生助手可根据建议调整随访计划。

### 23.3 科室主任查看科室情况

前置条件：科室内存在多名医生和多个患者。

步骤：

1. 科室主任登录。
2. 进入科室主任看板。
3. 查看患者总数、风险分布、随访完成率。
4. 按医生筛选患者。
5. 打开异常患者详情。

预期结果：

- 科室主任只能看到本科室相关数据。
- 统计数据与患者列表一致。
- 可查看患者详情和报告随访建议。

### 23.4 小程序随访异常处理

前置条件：患者已有随访任务。

步骤：

1. 患者通过小程序提交随访反馈，公开链接作为补充入口。
2. 反馈中包含异常症状或复查异常。
3. 系统标记异常待处理。
4. 健康管理师查看异常任务。
5. 健康管理师/医生助手联系患者并记录处理结果。
6. 如需调整随访计划，操作人员可参考医生已填写的报告随访建议。

预期结果：

- 异常任务状态流转完整。
- 患者小程序反馈、公开链接反馈和处理结果均可追溯。
- 患者状态从异常待处理恢复为随访中或已完成。

## 24. 原型与现有系统调整建议

当前 Vue 原型和后端服务已有较多基础能力，建议不要推翻重做，而是在现有基础上做医院场景收敛。

建议调整：

- 将当前“工作台”明确拆分为操作工作台、医生工作台、科室主任看板。
- 将患者详情页作为主入口，承载建档、结节、报告、报告随访建议、随访全链条。
- 将“医生IP打造/AI超级员工”等偏营销能力从医院一期主流程中弱化或隐藏。
- 将随访知识库与模板保留为系统特色，但一期重点放在规则推荐和人工确认。
- 将多场景入口收敛到医院场景，减少药店、体检、家医等非本期场景干扰。
- 将风险分层文案明确为健康管理分层，不表达诊断结论。

## 26. 文档使用方式

本需求书建议分三步使用：

1. 产品设计：基于本需求书绘制医生工作台、科室看板、患者详情页、小程序随访页和随访任务页面。

3. 验收测试：按典型验收用例验证角色权限、患者多结节管理、报告随访建议、小程序随访和科室看板。
